# COURSE — MVP (Django + Vue 3)

Полноценная (не HTML-макет) реализация платформы онлайн-обучения по архитектуре
из инструкции: backend на Django REST Framework + JWT, frontend на Vue 3 / Vite / Pinia.
Визуальный стиль (тёмно-синий + золото) перенесён из исходного прототипа `Cours.html`.

## Важно перед запуском

1. Распакуйте `course_mvp.zip` в **отдельную чистую папку**, например `D:\course_mvp`.
   Внутри должна появиться структура:
   ```
   D:\course_mvp\my_course_project\backend\...
   D:\course_mvp\my_course_project\frontend\...
   ```
2. Все команды ниже выполняются **из этих папок** (`...\my_course_project\backend`
   и `...\my_course_project\frontend`), а не из корня диска и не из какой-то другой
   существующей у вас папки с проектом — иначе получите ошибки от npm/python про
   чужие пакеты или "путь не найден".

## Что реализовано в MVP

- Реальная база данных (SQLite для простоты запуска), а не localStorage.
- JWT-аутентификация: вход, обновление токена. Самостоятельная регистрация
  и инвайт-коды убраны — доступ выдаёт только администратор (раздел «Ученики»),
  логин и временный пароль приходят на почту ученика.
- Роли: администратор / ученик (кастомная модель User).
- Курсы → модули → уроки, с реальной серверной логикой блокировки модулей
  (модуль открывается, только когда все уроки предыдущего просмотрены и —
  если требуется — тест сдан выше порога).
- Тесты с проверкой ответов на сервере (варианты и правильность не палятся на фронте).
- Админ-панель (API + Vue-страницы): ученики (создание с автогенерацией пароля
  и отправкой письма в консоль), инвайт-коды (генерация, список, статус использования).
- Конструктор тренинга во фронтенде (раздел «Тренинги» у администратора): тумблеры
  модуля (обязательный тест, порог прохождения, разрешение скачивания), добавление/
  редактирование/удаление уроков.
- Редактор тестов во фронтенде (раздел «Тесты» у администратора): создание теста для
  модуля, добавление/удаление вопросов и вариантов ответа, отметка правильного варианта.
- Прогресс ученика (раздел «Прогресс» у администратора): выпадающий список учеников,
  по каждому — прогресс по всем модулям всех тренингов (уроки, тесты, блокировки).
- У ученика: полное меню — Тренинги (курс → модуль → урок), Тестирования (сводный
  список всех тестов по всем тренингам), Чаты, Расписание, Мой профиль.
- Смена пароля учеником (кнопка «Сменить пароль» в профиле).
- Реальная загрузка видео к уроку и материалов (слайды/изображения, аудиозаписи,
  PDF-документы) администратором — файлы сохраняются на сервере (`backend/media/`) и
  реально доступны ученику для просмотра/скачивания на странице урока.
- Создание новых тренингов и модулей прямо во фронтенде (кнопки «+ Добавить тренинг»
  и «+ Добавить модуль» в разделе «Тренинги» у администратора) — не только редактирование
  «Основы визажа», можно завести сколько угодно новых курсов.
- Анимация на экране входа (плавное появление карточки, полей и лёгкое свечение
  логотипа; при успешном входе — анимированный переход в приложение).
- Раздел «Новости» (бывшее «Расписание»): полноценное описание у каждой новости,
  необязательная ссылка на внешний ресурс, модалка «Подробнее» с полным текстом;
  у администратора — поиск по новостям и фильтр по тренингу.
- Уведомления: колокольчик — глобальный компонент поверх любой страницы
  (не закрывается при переходе между разделами), «Прочитать всё» работает
  надёжно на обеих сторонах (админ/ученик).
- Урок: единая загрузка видео (файл или ссылка) и любых файлов (слайды, аудио,
  PDF, презентации) с автоопределением типа — без ручного выбора; длительность
  видео определяется автоматически из самого файла. Короткое описание урока.
  Загруженное видео автоматически перекодируется на сервере в H.264+AAC/MP4
  (если на сервере установлен `ffmpeg`) — это гарантирует, что звук и видео
  воспроизводятся в любом браузере, даже если исходный файл был в экзотическом
  кодеке/контейнере. Если `ffmpeg` не установлен — файл сохраняется как есть.
- Урок отмечается просмотренным автоматически (по окончании видео/90%+
  просмотра) — отдельной кнопки больше нет.
- Комментарии под видео урока (с прокручиваемой лентой, новые видны внизу):
  администратору приходит уведомление с указанием курса/модуля/урока и автора.
- Чаты — двухпанельный интерфейс (список чатов слева, переписка справа) с
  сообщениями-«пузырьками», временем у каждого сообщения и разделителями дат,
  как в WhatsApp/Telegram; список чатов и поле ввода никогда не двигаются —
  прокручивается только лента сообщений (проверено: положение поля ввода
  не меняется ни при прокрутке, ни при добавлении новых сообщений).
- Голосовые сообщения в любом чате — кнопка-микрофон рядом с полем ввода,
  запись через микрофон браузера, отправка одним кликом, воспроизведение
  прямо в переписке через встроенный аудиоплеер. (Браузеры разрешают доступ
  к микрофону только на `localhost` или по `https://` — на обычном
  `http://` с другого устройства в сети браузер эту кнопку заблокирует,
  это ограничение самого браузера, а не приложения.)
- Настройки внешнего вида (тёмная/светлая тема) — в профиле ученика и в
  разделе «Настройки» у администратора, применяются во всём приложении.
- Прогресс ученика: поиск/фильтр по ученикам, сводная статистика и простые
  диаграммы прохождения по каждому тренингу и модулю, полная история попыток
  теста (не только лучший результат — видно каждую пересдачу), а также
  отдельный блок аналитики «сколько учеников прошли модуль» с фильтром по
  конкретному модулю.
- Активация/деактивация ученика — один клик по самому статусу в таблице
  «Ученики» (без отдельной дублирующей кнопки).
- В редакторе урока файлы (видео и любые материалы — включая Word/Excel/
  архивы/что угодно) можно прикреплять сразу, ещё до отдельного сохранения
  урока — урок при необходимости создаётся автоматически при первом файле.

## Автоматическая перекодировка видео (звук гарантированно слышен)

Backend автоматически перекодирует каждое загруженное администратором видео
урока в универсально совместимый формат (H.264 видео + AAC аудио в MP4) —
это решает ситуацию «видео смотрится, а звука не слышно», которая бывает
из-за экзотических кодеков в исходном файле. Ничего дополнительно
устанавливать не нужно: пакет `imageio-ffmpeg` (уже в `requirements.txt`)
несёт готовый ffmpeg-бинарник прямо внутри себя для Windows/macOS/Linux —
после обычного `pip install -r requirements.txt` перекодировка работает
сама, без настройки PATH и отдельной установки ffmpeg.
Если в системе к тому же установлен свой системный `ffmpeg` — используется он.

## Запуск backend — Windows (PowerShell)

```powershell
cd D:\course_mvp\my_course_project\backend

python -m venv venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass   # только если venv\Scripts\Activate.ps1 не запускается
venv\Scripts\Activate.ps1

pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

## Запуск backend — macOS / Linux

```bash
cd my_course_project/backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

## Запуск frontend (Windows / macOS / Linux — одинаково)

Откройте **второе, отдельное** окно терминала (backend должен остаться запущенным
в первом):

```powershell
cd D:\course_mvp\my_course_project\frontend
npm install
npm run dev
```

Откроется на `http://localhost:5173`, обращается к API по адресу из `VITE_API_URL`
(по умолчанию `http://localhost:8000/api`, см. `.env.example`). Если увидите ошибки
про чужие пакеты (react, zod, eslint-plugin-...) — значит `npm install` был запущен
не в этой папке, а в какой-то другой, где уже лежит другой проект с своим `package.json`.

## Запуск через Docker (Postgres + backend + frontend)

Проще всего для деплоя — поднять весь стек одной командой. Нужен только установленный
Docker и Docker Compose, ничего больше настраивать не нужно.

```bash
cd my_course_project
cp .env.example .env        # при желании поменяйте пароли/секреты внутри
docker compose up --build
```

Что произойдёт:

- поднимется контейнер **Postgres** (том `postgres_data` — данные не теряются
  при перезапуске);
- контейнер **backend** дождётся готовности базы, применит миграции, соберёт
  статику и запустит Django через `gunicorn` на порту `8000`
  (если задать `SEED_DEMO=True` в `.env` — при старте выполнится `seed_demo`);
- контейнер **frontend** соберёт Vue-приложение (`npm run build`) и раздаст его
  через `nginx` на порту `80`, проксируя `/api/`, `/media/` и `/static/` на backend.

Откройте `http://localhost` — это уже собранный фронтенд, обращающийся к API
через тот же домен (порт 80 не нужно указывать отдельно в `VITE_API_URL`).

Полезные команды:

```bash
docker compose logs -f backend       # логи backend (в т.ч. письма, если EMAIL_BACKEND=console)
docker compose exec backend python manage.py createsuperuser
docker compose exec backend python manage.py seed_demo
docker compose down                  # остановить (данные в volume сохранятся)
docker compose down -v               # остановить и удалить данные Postgres
```

Для локальной разработки без Docker (`npm run dev` / `runserver`) ничего менять
не нужно — Postgres используется только тогда, когда задана переменная
`DATABASE_URL`, при обычном запуске backend продолжает работать на SQLite.

## Тестирование

Backend (Django/DRF, стандартный тест-раннер):

```bash
cd backend
python manage.py test apps
```

Frontend (Vitest — юнит-тесты утилит и Pinia-сторов):

```bash
cd frontend
npm run test
```

## Проверено

- `python manage.py check` — без ошибок, миграции применяются чисто.
- `python manage.py test apps` — 56 тестов backend зелёные (аккаунты, курсы,
  админ-панель, уведомления, новости, перекодирование видео).
- `npm run build` — сборка фронтенда без ошибок.
- `npm run test` — 24 юнит-теста фронтенда зелёные.
- Двухпанельный чат и лента комментариев урока вручную проверены в браузере
  (headless Chromium + Playwright) — список чатов/поле ввода не двигаются,
  скроллится только лента сообщений/комментариев.
